# Лабораторные без физического робота

32 академических часа: 8 работ по 4 часа. Пререквизиты: основы Python, функции,
классы, графики, базовые представления об обратной связи. Студенты открывают
размещённый браузерный стенд, установки на их компьютеры нет.

## Общая организация

До занятия: прочитать контракт, подготовить закон управления или диаграмму состояний.
На занятии: дописать заготовку, провести серию опытов, объяснить результат.
После занятия: сдать исходник, параметры, отчёт и выводы. Преподаватель повторно
запускает код на собственной копии стенда с объявленными контрольными условиями.

Пример распределения 180 минут: 20 — постановка и теория; 70 — реализация;
50 — серия экспериментов; 25 — анализ; 15 — демонстрация и вопросы.
Сложные реализации требуют предварительной подготовки, а не написания с нуля за пару.

## 1. Контракт управления и диагностика

Сцена: пример API на площадке «Остановка у стены».

Реализовать три коротких состояния: движение, поворот, остановка. Сопоставить
вызовы клиента с журналом STX/JSON/ETX и ACK. Проверить противоположные знаки PWM,
ошибочный канал сервопривода и неизвестную команду. Отдельно перестать отправлять
команды после начала движения и наблюдать watchdog. Затем повторить с ping.

Сдать таблицу «команда → выходы → наблюдаемое поведение» и объяснить различие
между ACK, PWM, физической скоростью и достижением цели. Автоматический результат
сцены при этих опытах не является оценкой работы: здесь оценивается исследование API.

## 2. Идентификация учебной модели привода

Сцена: «Движение по коридору», номинальный профиль.

Реализовать программу серии одинаковых по длительности воздействий с различным PWM.
По времени и пройденному пути из отчёта оценить скорость, найти мёртвую зону.
Изменить длительность воздействия для оценки влияния разгона. Сравнить левый и
правый моторы в профиле возмущений. Геометрию проверяющей системы разрешено
использовать в отчёте для измерения, но не передавать в алгоритм управления.

Сдать график PWM → средняя скорость и оценку ошибки модели. Объяснить, почему
линейный пересчёт сантиметров во время движения не универсален.

## 3. Регулятор расстояния

Сцена: «Остановка у стены».

Реализовать P-регулятор, затем PI или PID. Учесть ограничения PWM, мёртвую зону,
интегральное насыщение и зону остановки. Использовать dt из исполнителя.
Сравнить настройки на вариантах 1…5. Критерий сцены: 30 ± 3 см, удержание 2 с,
скорости колёс <1,5 см/с, отклонение курса <0,15 рад, без столкновений за 22 с.

Сдать код, графики расстояния и воздействия, сравнение времени и ошибки.
Числовые нормативы относятся к объявленной модели, не к физическому роботу.

## 4. Фильтрация и недостоверные данные

Сцена: «Остановка у стены», профиль возмущений.

Реализовать медианный фильтр и/или экспоненциальное сглаживание. Сравнить с
регулятором без фильтрации. Исключать 999 до фильтрации; не подставлять 0.
Обрабатывать sensor_timestamp: повторный пакет не является новым измерением.
Использовать reading() для обнаружения устаревания и возобновления измерений.

Отдельно объяснить реакцию на потерю телеметрии в интервале 5,0…5,65 с. В профиль
также входят асимметрия привода и шум; для устойчивого курса могут потребоваться
боковые измерения. Полный успех динамической сцены — дополнительная часть,
основная оценка работы — корректная фильтрация, остановка и восстановление.

## 5. Следование по коридору

Сцена: «Движение по коридору».

По FL/FR/RL/RR оценить смещение и перекос платформы. Реализовать P/PD-коррекцию
разности PWM. Сравнить движение без коррекции и с ней при разных стартах.
Учесть, что близко к торцу лучи начинают измерять переднюю стену.

Критерий: x ≥ 212 см за 28 с без столкновения, после x > 75 см боковое отклонение
от оси ≤14 см. Истинные x/y используются только проверяющей системой.

## 6. Реактивная навигация

Сцена: «Обход препятствий».

Реализовать автомат DRIVE/TURN/RECOVER либо непрерывное реактивное управление.
Добавить гистерезис, выбор направления по нескольким датчикам, тайм-аут состояния.
Препятствия в разных вариантах меняют положение. Координаты препятствий не входят
в API робота. Это задача реактивной навигации, а не гарантированный глобальный планировщик.

Критерий: x ≥ 275 см за 40 с, без столкновений. Сдать автомат/закон управления,
таблицу результатов для пяти вариантов и разбор неудачного случая.

## 7. Неблокирующий автомат манипулятора

Сцена: «Автомат манипулятора».

Исполнить позы (канал 0, канал 1), мкс:
(1450,1400) → (1300,1400) → (1300,1750) → (1550,1750) → (1350,1750) → (1350,1400).
Для каждой дождаться импульса в допуске ±10 мкс и выдержать не менее 0,3 с.
Вся последовательность — за 16 с; платформа должна стоять.

Сдать диаграмму автомата и журнал импульсов. Переходы по ACK без ожидания
формируемого импульса не выполняют критерий. Это не проверка физического захвата кубика.

## 8. Интеграция транспортной миссии

Сцена: «Доставка груза».

Реализовать APPROACH/LOAD/RETURN/UNLOAD/DONE с тайм-аутами и обработкой отсутствия
дальности. Доехать до правой станции, остановиться и закрыть захват; вернуться
к левой, остановиться и открыть захват. Возврат задним ходом допустим.

Критерий: загрузка при x ≥ 272 см, импульс захвата ≥1740 мкс; разгрузка при
x ≤ 55 см, импульс ≤1410 мкс. На каждой станции 0,5 с при скоростях <1,5 см/с.
Общий лимит 55 с, столкновения запрещены. Объект условно загружается на станции;
манипуляционные контакты и масса груза не моделируются.

Сдать исходник, схему автомата, пять прогонов, объяснение поведения при отказах.

## Критерии оценки

| Составляющая | Доля |
|---|---:|
| Алгоритм и объяснение | 40% |
| Эксперименты и анализ | 30% |
| Нештатные ситуации | 20% |
| Воспроизводимость | 10% |

Контрольный список приёмки: исходник совпадает с обсуждаемым решением; код использует
только SDK; студент объясняет знаки и единицы; повторный запуск воспроизводит
результат; неудачные заезды разобраны. Заранее выдайте студентам диапазон тестовых
условий. В клиентском приложении скрытых тестов нет; отчёт сам по себе не основание
для оценки. Версия модели входит в отчёт и должна совпадать при сравнении решений.

## Дальнейшее расширение

Для движения по линии и ArUco понадобится отдельный контракт камеры и генерация
кадров, меняющихся от движения робота. Записанные изображения подходят для
проверки распознавания, но не для оценки замкнутого управления. Такие работы
не входят в реализованные пять сцен этой версии.
