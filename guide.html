Как устроено решение

Определите класс Controller. Перед каждым заездом среда создаёт новый экземпляр и вызывает step(robot, dt) раз в 0,05 секунды модельного времени. robot уже подключён к виртуальному ESP32. Состояние алгоритма сохраняйте в self.

from pesok_sdk import ESP32Client

class Controller:
    def __init__(self):
        self.elapsed = 0.0

    def step(self, robot: ESP32Client, dt: float):
        self.elapsed += dt
        distance = robot.distance("laser")
        if distance is None or distance < 40 or self.elapsed > 2:
            robot.stop()
        else:
            robot.raw_motors(120, 120)

Это пример работы с API, а не решение лабораторной по регулированию. Он показывает чтение датчика, обработку отсутствующего измерения, PWM и таймер.

  1. Выберите задание и прочитайте критерии.
  2. Допишите заготовку. Кнопка «Пример API» заменяет код небольшим примером движения.
  3. «Запустить» выполняет один вариант и показывает запись заезда.
  4. «Проверить 5 вариантов» запускает варианты N, N+1, …, N+4.
  5. Включите «Шум и возмущения» для дополнительного эксперимента.
  6. Скопируйте отчёт с исходным кодом для сдачи преподавателю.

step() должен быстро возвращать управление. Не используйте внутри него while True, time.sleep() и циклы ожидания датчика. Для ожидания накопите dt в поле объекта и вернитесь из текущего шага.

Кнопка «Остановить» прерывает и вычисление, и просмотр записи. Вычисление ограничено 12 секундами реального времени после загрузки Python. Коэффициент 1× / 3× / 8× меняет только скорость просмотра: он не влияет на физику и критерии.

Методы управления возвращают True при положительном ACK и False при отказе. Ошибка аргументов высокоуровневого метода вызывает ValueError. Приведите вычисленное воздействие к целому числу и ограничьте диапазон:

pwm = int(round(max(-255, min(255, calculated_pwm))))
if not robot.raw_motors(pwm, pwm):
    robot.stop()

None означает «нет достоверного расстояния», а не ноль и не свободный путь. Если выбранная стратегия останавливает робот при потере данных, после восстановления измерений она должна уметь продолжить движение.

Координаты и датчики учебной модели

Мировая ось X направлена вправо, Y вверх. На старте робот смотрит вдоль +X. В системе робота X направлена вперёд, Y влево. Положительный угол поворота направлен против часовой стрелки. Поэтому raw_motors(-120, 120) поворачивает влево, raw_motors(120, -120) — вправо.

Что именно проверяется на уровне протокола

Клиент сериализует команды в 0x02 + JSON UTF-8 + 0x03. Виртуальный ESP32 разбирает кадр, обновляет выходы и формирует ACK и телеметрию тем же способом. Размер кадра SDK — не более 512 байт.

→ STX {"cmd":"raw","left":120,"right":100} ETX
← STX {"type":"ack","cmd":"raw","ok":true,"timestamp":100} ETX

Измерения обновляются раз в 100 мс, телеметрия раз в 50 мс. sensor_timestamp позволяет отличить новое измерение от повторной отправки. Значения времени в пакете — миллисекунды часов виртуального ESP32. Не сравнивайте их напрямую с системными часами компьютера.

Через 500 мс без команды заданный PWM становится нулевым. Любая разобранная команда с непустым cmd, включая ping, обновляет этот watchdog, как в прошивке. В учебном клиенте нет фонового keepalive: обновляйте движение каждым шагом. Флаг emergency дублирует link_lost и не сообщает о препятствии.

Кадры LED в текущей учебной модели не реализованы. Команды safety_auto, safety_manual и reset_emergency подтверждаются как игнорируемые, согласно прошивке. Неизвестная команда получает отрицательный ACK.

Учебный pesok_sdk.ESP32Client поддерживает описанное подмножество API. Исходный rpi_controller.esp32_client.ESP32Client остаётся клиентом физического робота с Serial и фоновыми потоками. Он не загружается в браузер. Методы distance() и reading() добавлены только в учебном SDK; аргументов seconds и wait_ack в нём нет.

Условия эксперимента и ограничения

Корпус проверяется как круг радиусом 12 см, колёсная база — 22 см. Номинальная модель скорости одного колеса: 0 при |PWM| ≤ 75; иначе знак(PWM) × (|PWM| − 75) / 180 × 65 см/с. Скорость меняется с постоянной времени 0,16 с. Это учебные коэффициенты, не результат измерения реального привода.

При включённых возмущениях порог PWM выбирается в диапазоне 68…82, коэффициенты левого и правого моторов — независимо в диапазоне 0,91…1,03. Шум дальномеров имеет стандартное отклонение 1,2 см; вероятность пропуска измерения — 5%. Между 5,0 и 5,65 с прекращается отправка телеметрии. Начальные условия определяются номером варианта.

Переход сервоприводов повторяет скорость изменения импульса прошивки: 10 мкс каждые 15 мс. В заданиях на манипулятор и доставку оцениваются последовательность импульсов и состояние платформы. Захват, масса и трение кубика не моделируются.

Камеры, ArUco и изображение линии в этой версии отсутствуют. Полигон на экране — вид проверяющей системы; это не кадр бортовой камеры. Задачи курса в этой версии используют только контракт ESP32.

Как организовать занятия и оценивание

Практикум размещается как статический сайт. Студенты открывают ссылку, получают заготовку и отправляют исходный код в принятую систему сдачи работ. Их браузер считает симуляцию локально; аккаунты, база данных и сервер исполнения Python для самопроверки не нужны.

Для приёмки откройте свою эталонную копию стенда, вставьте исходный код студента, выберите задание и проведите контрольные заезды с заранее определёнными вариантами. Объявите диапазоны возмущений и критерии до выдачи работы. Номер версии модели и SHA-256 исходного кода включаются в отчёт.

Браузерный JSON-отчёт редактируем, а исходники тестов открыты. Он помогает разбирать результат, но сам по себе не подтверждает оценку. Студенческому алгоритму по правилам разрешены только методы SDK; доступ к внутренностям simulator, модели и проверяющим функциям запрещён условиями работы. Изоляции от такого доступа внутри одного Python-процесса нет. Для скрытых тестов и защищённого автоматического оценивания потребуется отдельный сервер с изолированным запуском.
