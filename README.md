# Браузерный практикум «Песок»

Статический учебный сайт: Python-редактор, 2D-модель дифференциального робота,
совместимое подмножество ESP32Client, пять сцен, автоматическая самопроверка,
воспроизведение заезда, журнал команд и отчёт вместе с исходным кодом.

Отдельный репозиторий практикума:
[kurorodev/pesokbot_education](https://github.com/kurorodev/pesokbot_education).
Все файлы сайта находятся в корне репозитория.

Студентам не нужны установка Python, Webots, расширения или ручное скачивание
файлов. По ссылке браузер загружает страницу и Python/WebAssembly. Первый запуск
требует интернета и доступа к cdn.jsdelivr.net. Это не работа без передачи данных
и не полностью автономный офлайн-сайт.

## Пользование

Откройте размещённый `index.html`, выберите задачу и допишите класс `Controller`.
Метод `step(robot, dt)` вызывается каждые 0,05 с модельного времени. Состояние
сохраняйте в `self`. Подробный справочник доступен прямо в [guide.html](guide.html).

«Запустить» выполняет один вариант и показывает запись заезда; «Проверить 5
вариантов» выполняет N…N+4. Переключатель возмущений задаёт дополнительный профиль
эксперимента. Код каждой задачи сохраняется в localStorage этого браузера.
«Копировать отчёт с кодом» позволяет сдать решение без скачивания файлов.

Время симуляции отличается от реального времени и не зависит от скорости
просмотра. Бесконечный цикл прекращается завершением Worker; время вычисления
после загрузки Python ограничено 12 секундами. Страница остаётся отзывчивой.

## Размещение для студентов

Разместите содержимое **этой папки** на имеющемся HTTPS-сайте кафедры либо на
статическом хостинге. Сборки, npm, Python на сервере, базы данных и ключей API нет.
Файлы `*.js`, `*.json`, `*.py` должны отдаваться как статические ресурсы, а не
исполняться веб-сервером. JavaScript-модулям нужен корректный MIME-тип.

Нужны: `index.html`, `guide.html`, `style.css`, `app.js`, `worker.js`,
`lessons.json`, `pesok_sdk.py`, `simulator.py`, `README.md`, `CONTRACT.md`, `LABS.md`.
Исходники учебного SDK, модели и тестовых условий публичны по конструкции.
Не размещайте весь репозиторий робота, журналы и служебные файлы.

Прямое открытие `index.html` через `file://` не поддерживается: браузер ограничивает
загрузку модулей и файлов. Для преподавательского локального предпросмотра из корня
этого репозитория, если Python уже установлен:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

Адрес предпросмотра: `http://127.0.0.1:8765/`. Это адрес только вашего компьютера,
не ссылка для студентов. Публичное размещение — отдельный шаг на выбранном хостинге.

## Проверка решений

Браузерный отчёт — самопроверка, а не защищённая ведомость. Преподаватель получает
**исходный код**, повторно запускает его в своей эталонной копии сайта и использует
объявленные критерии. Другие номера вариантов позволяют менять начальные условия.
Контролируйте, что решение пользуется только учебным API и не читает внутренности
модели. Python в Worker не создаёт изоляцию студенческого кода от модулей симулятора.

Для скрытых тестов и массовой автоматической выставляемой оценки нужен отдельный
сервер с изолированным выполнением. В этой версии такого сервера нет. Не запускайте
полученный от студентов Python-код обычным `exec` на компьютере преподавателя или
сервере: это выполнение произвольного кода. Для предлагаемой ручной приёмки используйте
эталонную браузерную среду без данных и внутренних ресурсов кафедры.

Отчёт фиксирует версию модели, условия, номер варианта, исходник, SHA-256 исходника,
время, путь и причину успеха/неуспеха. Геометрическая проверка использует состояние
модели, а не значения, сообщённые решением студента. Случайность среды определяется
seed; если алгоритм использует собственную случайность, студент также фиксирует её seed.

## Как связан SDK с настоящим роботом

`pesok_sdk.ESP32Client` — отдельный учебный фасад на чистом Python. Форматы
STX/JSON/ETX, команды движения, импульсы и поля телеметрии соответствуют прошивке.
Его базовые методы повторяют имена и смысл методов `rpi_controller/esp32_client.py`.
Подробности и отличия: [CONTRACT.md](CONTRACT.md).

Физический клиент и прошивка не изменены. В браузере нет обращения к Serial,
Picamera2 или потокам Python. Прямого подключения этой страницы к физическому роботу
в этой версии нет. Для переноса контроллера нужен исполнитель на Raspberry Pi и
адаптация двух дополнительных методов проверки свежести `distance`/`reading`.

## Границы модели

Пять дальномеров моделируются одиночными лучами. Размеры, их расположение и параметры
привода явно объявлены в справочнике; они не получены идентификацией физического робота.
Модель проверяет обучение алгоритмам, а не гарантирует переносимость коэффициентов PID.
Не моделируются камера, ArUco, изображение линии, акустические помехи, проскальзывание
и контакты захвата с грузом. Задания на сервоприводы оценивают импульсы и логику;
«доставка» использует условную загрузку на станции.

Виртуальный ESP32 не является эмулятором процессора и не выполняет C++-прошивку.
Он воспроизводит нужное для курса поведение протокола. ACK синхронный; обрывы
пакетов, очереди и задержки ACK в динамическом заезде не моделируются. Потоковый
декодер отдельно проверяется тестами.

