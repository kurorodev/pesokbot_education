# Контракт ESP32Client для лабораторных

Версия учебной модели: 1.0.0. Источники фактического протокола:
`esp32_hardware/src/communication/serial_protocol.cpp`,
`esp32_hardware/src/system/task_manager.cpp`,
`esp32_hardware/src/config/constants.h`.

## Два клиента

| Свойство | Физический клиент | Учебный клиент |
|---|---|---|
| Импорт | `rpi_controller.esp32_client.ESP32Client` | `pesok_sdk.ESP32Client` |
| Подключение | Serial, `connect()` или контекстный менеджер | Готовый экземпляр передаётся в `Controller.step` |
| Обмен | Serial, фоновые потоки, ACK с тайм-аутом | Синхронный обмен байтовыми кадрами с виртуальным ESP32 |
| Keepalive | Фоновый ping | Отсутствует; команды обновляются из step |
| Длительность движения | Есть аргумент `seconds` | Ожидание через состояние и dt |
| Безопасное чтение дальности | Нет отдельного метода | `distance()` / `reading()` |
| LED, сервоприводы по углу | Поддерживаются | В учебное подмножество не входят |

Это совместимость описанного подмножества, не полная взаимозаменяемость двух классов.
Методы Robot вида `forward(cm)` — другой, миссионный уровень. В ESP32Client
`forward(speed)` аргумент является PWM, не расстоянием.

## Формат кадров

`b'\x02' + JSON UTF-8 + b'\x03'`. Высокоуровневый учебный SDK допускает кадр не
более 512 байт, включая маркеры; это консервативнее входного буфера прошивки.
Декодер допускает частичные кадры, несколько кадров в одном чтении и текстовый шум
вне кадров. Новый STX сбрасывает незавершённый кадр. Повреждённый JSON пропускается.

### Команды

| Команда | Поля | Смысл |
|---|---|---|
| `raw` | `left`, `right` | Заданные PWM −255…255 |
| `stop` | — | Обнулить PWM |
| `forward`, `backward` | `speed` | Движение двумя моторами |
| `turn_left`, `turn_right` | `speed` | Противоположные PWM для разворота |
| `servo_us` | `channel`, `pulse_us` | Целевой импульс сервопривода |
| `ping` | — | Подтверждение и обновление watchdog |

Высокоуровневые методы SDK проверяют тип int, диапазоны PWM, каналы 0/1 и импульсы
1000…2100 мкс, выдавая ValueError при ошибке. Для `forward` и поворотов speed должен
быть 1…255. Остановка задаётся `stop()`, не `forward(0)`.

На уровне произвольного `send_command` модель повторяет прошивку: PWM и импульсы
ограничиваются диапазоном. У команд движения отсутствующий либо неположительный
speed заменяется на 220 для прямого хода и 150 для поворота. Неверный канал даёт
ACK с `ok=false`, `message=invalid_servo`. Неизвестная команда — `unknown_command`.
`safety_auto`, `safety_manual`, `reset_emergency` возвращают положительный ACK
с `message=ignored_host_authority`. LED в этой модели не реализованы.

ACK: `type="ack"`, `cmd`, `ok`, необязательное `message`, `timestamp` в мс.
ACK подтверждает обработку, а не достижение положения. Идентификатора отдельного
запроса и CRC в протоколе нет. Учебный обмен синхронный, ACK не теряются.

### Телеметрия

| Поле | Единицы и значение |
|---|---|
| `type` | `telemetry` |
| `control_authority` | `host` |
| `fl`, `fr`, `rl`, `rr` | Расстояние в см; 999 при ошибке/выходе за предел |
| `laser` | Целые см; 999 при ошибке/выходе за предел 200 см |
| `motor_left`, `motor_right` | Заданные PWM; не обороты и не скорость |
| `servo_0_us`, `servo_1_us` | Текущие формируемые импульсы в мкс |
| `link_lost`, `emergency` | Один флаг потери командной связи |
| `sensor_timestamp` | Время последнего набора измерений в мс ESP32 |
| `sensor_age_ms` | Возраст набора на момент формирования пакета |
| `timestamp` | Время формирования пакета в мс ESP32 |

Измерения: 100 мс. Телеметрия: 50 мс. Две телеметрии могут содержать одно измерение.
Watchdog: обнуление PWM после 500 мс без команд. Ping тоже обновляет watchdog.
Сервоприводы: изменение формируемого импульса на ≤10 мкс каждые 15 мс.

`get_distances()` сохраняет сырые 999 для совместимости. `distance(name)`
возвращает None при 999, недопустимом значении, отсутствии измерения или возрасте
более 250 мс. `reading(name)` возвращает `RangeReading(cm, age_ms, valid)`.
Возраст = sensor_age_ms + прошедшее после приёма пакета время часов исполнителя.
Отсутствие новых сообщений не делает старые данные свежими.

## Исполнитель алгоритма

```python
class Controller:
    def __init__(self):
        self.elapsed = 0.0

    def step(self, robot, dt):
        self.elapsed += dt
        # Один шаг: прочитать данные, принять решение, отправить команду.
        robot.stop()
```

dt = 0.05 с модельного времени. Новый экземпляр Controller создаётся для каждого
заезда. Команда удерживается до следующей команды или watchdog. При завершении
заезда/исключении исполнитель отправляет stop. Из-за инерции stop не означает
мгновенное исчезновение физической скорости.

Разрешены стандартная библиотека Python, поля self, методы SDK. Использование
`simulator.World`, внутренних полей transport, координат модели и функций оценки
запрещено правилами учебной работы. Это правило, не техническая песочница: студент
может исследовать клиентские исходники. Оценка требует повторного запуска и защиты.
